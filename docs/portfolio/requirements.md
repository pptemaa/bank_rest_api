# Требования к управлению картами

## Цель и участники

Сервис позволяет администратору выпускать карты пользователям и менять их статус, а пользователю — смотреть собственные карты и переводить баланс между ними. Роли: `ADMIN`, `USER`. Данные хранятся в PostgreSQL; доступ к защищенным методам требует JWT.

## Сценарии

**US-1. Выпуск.** Администратор создает карту существующему пользователю. Новая карта получает статус `ACTIVE`, нулевой баланс и срок действия через три года.

**US-2. Просмотр.** Пользователь получает список только своих карт с пагинацией. Номер в ответе маскируется до последних четырех цифр.

**US-3. Перевод.** Пользователь переводит положительную сумму между двумя принадлежащими ему активными картами при достаточном балансе источника.

**US-4. Управление статусом.** Пользователь запрашивает блокировку собственной карты; администратор блокирует или активирует карту.

## Правила и критерии приемки

| ID | Правило | Проверка |
| --- | --- | --- |
| FR-1 | Выпуск доступен только `ADMIN` | `POST /api/cards?userId=...` возвращает 201 и карту с `ACTIVE` и балансом 0 |
| FR-2 | Пользователь видит свои карты | `GET /api/cards/me` возвращает страницу карт текущего пользователя |
| FR-3 | Чужие карты не участвуют в переводе | Попытка перевода с/на чужую карту дает 400; баланс не меняется |
| FR-4 | Сумма перевода положительна | Пустая, нулевая или отрицательная сумма дает 400 |
| FR-5 | Достаточно средств | При нехватке средств возвращается 400; списания нет |
| FR-6 | Обе карты активны | Заблокированная карта вызывает 400 |
| FR-7 | Перевод атомарен | Изменение балансов двух карт выполняется в одной транзакции `@Transactional` |
| FR-8 | Номер маскируется в карточке API | `CardResponseDto.cardNumber` содержит только последние четыре цифры |

## Ограничения текущей версии

- Код не проверяет перевод карты на саму себя; такой запрос не следует считать отдельным поддержанным сценарием.
- Статус `EXPIRED` есть в модели, но автоматический перевод по истечении срока и проверка даты при переводе отсутствуют.
- Номер карты в БД не зашифрован. Пароль пользователя хэшируется BCrypt — это другой механизм.
- Нет endpoint для пополнения и таблицы истории переводов. Для демонстрации перевода баланс задается вручную в БД.
- При параллельных переводах нет явной блокировки строк или версионирования; гарантии конкурирующих операций следует отдельно проверить.
